# ВышКат

ИДЗ №1

Используется C# .NET 10

## Запуск

```bash
dotnet restore ihw1.sln
dotnet run --project VyshKat
dotnet test ihw1.sln
```

## Ввод из файла

```bash
dotnet run --project VyshKat -- --input demo-input.txt
```

`demo-input.txt` показывает пустые отчёты, приём разных видов транспорта и вещей,
отказ техосмотра, занятый номер, отчёты и повторную приёмку после ремонта.
До повторной приёмки получается 6 объектов и 13 кВт·ч/сутки, после — 7 объектов
и 17 кВт·ч/сутки.

## Правила учёта

- Инвентарный номер — положительное целое число, уникальное для транспорта
  и вещей. Имя не может быть пустым.
- Транспорт принимается только после решения `IServiceCenter`.
  Учебный `ServiceCenter` проверяет признак технической исправности,
  который вводит оператор. Вещи принимаются без техосмотра транспорта.
- Отказ или дубликат не меняют баланс. Номер отклонённого транспорта остаётся
  свободным для повторной приёмки.
- Простота транспорта — от 1 до 10. Для новичков подходит принятый транспорт
  с простотой от 6 включительно.
- Отчёт считает транспорт, вещи и все объекты. Энергия суммируется по всем
  принятым `IEnergyConsumer`, включая зарядные станции. Передача энергии
  от станции к транспорту отдельно не моделируется.
- Расход неотрицателен; при вводе разрешены точка и запятая.
  Обычный велосипед, шлем и пассивная док-станция электричество не потребляют.
- Неверный ввод вызывает повторный запрос. Конец ввода завершает программу;
  неполный объект не добавляется. Отсутствующий файл даёт сообщение и код выхода 1.

## Как устроено решение

- [Domain](VyshKat/Domain): `InventoryItem` хранит общие номер и имя;
  `Transport` и `Equipment` разделяют транспорт и вещи. Конкретные классы —
  самокат, велосипед, электровелосипед, шлем, зарядная станция и док-станция.
  `IInventoryItem` и `IEnergyConsumer` описывают независимые возможности.
- [FleetService](VyshKat/Services/FleetService.cs): хранит баланс по номерам,
  вызывает техосмотр и предоставляет данные для отчётов. Списки возвращаются
  снимками, поэтому их изменение не меняет внутренний баланс.
- [ConsoleApplication](VyshKat/ConsoleUi/ConsoleApplication.cs): выполняет
  команды меню и выводит результаты.
- [ConsoleInput](VyshKat/ConsoleUi/ConsoleInput.cs): читает и проверяет ответы
  из `TextReader`; одинаково работает с консолью и файлом.
- [Program](VyshKat/Program.cs): выбирает источник ввода и создаёт DI-контейнер.
- [AddVyshKat](VyshKat/Services/ServiceRegistration.cs) регистрирует общий для
  одного запуска баланс и реализацию техосмотра. Эта же регистрация используется
  в тестах.

## SOLID и решения по архитектуре

| Принцип | Где используется |
| --- | --- |
| SRP | Техосмотр, баланс, проверка ввода и команды меню разделены по классам. |
| OCP | `FleetService` работает с базовым транспортом и интерфейсами возможностей; перечня конкретных видов в нём нет. |
| LSP | Наследники `Transport` сохраняют общий контракт номера, простоты и исправности; новый вид участвует в тех же отчётах. |
| ISP | Шлему достаточно `IInventoryItem`, а электрические устройства отдельно реализуют `IEnergyConsumer`. |
| DIP | `FleetService` получает `IServiceCenter` через конструктор; реализация выбирается при сборке приложения. |

**Наиболее явно применён DIP:** тесты подменяют техосмотр через DI, не меняя
`FleetService`.

**Сознательно ограничен OCP в меню:** создание транспорта использует `switch`.
Для нового вида придётся добавить пункт ввода, но сервис учёта и отчёты останутся
прежними. Для трёх видов это проще отдельной системы фабрик или плагинов.
Дополнительные интерфейсы для каждого сервиса и отдельные проекты слоёв
для этого объёма не понадобились.

**Расширение:** новый транспорт наследует `Transport` и при необходимости
реализует `IEnergyConsumer`. Сотрудник должен быть отдельной моделью, поскольку
он не инвентаризируется. Для склада с партиями, остатками и выдачей понадобится
свой сервис; отдельную инвентарную вещь можно добавить как наследника `Equipment`.

## Тесты

В [FleetServiceTests](VyshKat.Tests/FleetServiceTests.cs):

- `AddTransport_UsesInspectionDecisionFromDi` заменяет `IServiceCenter` через
  `services.Replace(...)`. Fake возвращает решение, противоположное исправности
  транспорта: проверяется, что приёмка зависит именно от внедрённого сервиса.
- `GetBeginnerTransport_UsesInclusiveThreshold` фиксирует границу 5/6.
- `NewTransportType_WorksWithoutChangingFleetService` добавляет тестовый вид
  транспорта без изменений рабочего сервиса.
- Остальные проверки охватывают отказ, дубликаты, повторную приёмку и отчёты.

[DomainTests](VyshKat.Tests/DomainTests.cs) проверяют ограничения модели и
настоящий техосмотр. [ConsoleApplicationTests](VyshKat.Tests/ConsoleApplicationTests.cs)
проверяют меню, все типы, исправление неверного ввода, файл и конец потока.

Покрытие всего приложения:

```bash
dotnet test ihw1.sln --collect:"XPlat Code Coverage"
```

Отчёт появится в `VyshKat.Tests/TestResults`
